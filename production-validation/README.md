# Production startup validation — Analyzer 0.5.2

Both isolated startup probes passed against the exact remapped Analyzer SHA-256 recorded in `production-validation.json`. These launches used the official Minecraft 1.21.4 client, Fabric Loader 0.16.14, Fabric API 0.119.4+1.21.4 and production intermediary mappings. Fabric's development flag was false. The launcher used a local test name and a dummy access token; no account credentials, user Prism instance, saved world or public game server were used.

With the unchanged official Baritone API Fabric 1.13.1 JAR installed, Fabric loaded its nested native helper, the API initialized, and the real Automation screen displayed **BARITONE CONNECTED**. Without that optional mod, Analyzer still initialized all 123 modules and rendered the same real Automation screen with **BARITONE REQUIRED**, an installation explanation and disabled execution. Both captures are actual 1280 × 800 framebuffers. Both reached the normal title screen first, reported GL error 0, and stopped Minecraft normally.

The logs retain validation markers and runtime messages. Absolute local filesystem paths were normalized to `<workspace>` and `<user-home>` for portability. The corresponding screenshot and log hashes are recorded in the manifest.

`ProductionProbe.java` is the original, test-only Fabric client entrypoint. It uses reflection for production Minecraft names so it has no development namespace dependency. It waits for actual rendered screens, checks optional dependency state, takes the framebuffer screenshot and requests a normal shutdown. It is excluded from the Analyzer production JAR and ordinary Prism instance.

`probe_analyzer_production.py` is the original runner. To reproduce in a prepared Analyzer workspace, run `python probe_analyzer_production.py --workspace <workspace> --analyzer <production-remapped-jar> --run`. Its `work/` folder must already contain the Java 21 runtime and verified Minecraft/Fabric libraries and assets used by the project. Running without `--run` only prepares fresh isolated folders. The runner verifies cached vanilla library SHA-1 identities, the official Baritone SHA-256 and the remapped Analyzer metadata before launching.

These probes verify production startup, optional dependency handling and the actual Automation interface. Real Survival pathfinding, mining, inventory operations, shelter patching and controller safeguards are documented separately in the complete integrated-server smoke validation. These startup probes do not claim a public-server spawn escape or a complete autonomous enchanted-armor expedition.

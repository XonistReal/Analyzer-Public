# Automation motion and planning — 0.10.3

This update addresses the reported left/right camera hunting, backward turns on one-block descents and unnecessary planning delays. Turn speed, acceleration, break/place pacing and the user's saved profiles remain configurable and preserved.

The camera integrates acceleration, cruise and braking inside each tick instead of applying an endpoint velocity for the entire tick. Fixed targets brake before arrival and stop within the acceleration limit. A sudden new target inside an existing stopping distance can require one physical crossing; the controller then settles rather than repeatedly hunting. Walking holds pitch, exactly vertical block aims retain the existing yaw, and manual/other-owner camera changes do not inherit stale angular momentum. A movement child no longer erases its parent worker's camera state.

Mining releases movement to brake at an already reachable face rather than planning another route to its own cell center. A valid standing approach stays committed until invalidated; a selected first excavation step is reused only after the same fresh support, headroom, hazard and rejection checks as a new search. Block breaking still requires the actual visible crosshair and ordinary server timing.

Resource observations run nearest first. A bounded max-heap retains the nearest 64 checked candidates, and reachable nearby resources can be selected before the distant survey completes. Once the batch is full, more distant observations cannot improve it and are deferred. The full 98,441-cell window remains available when nearby sources are absent. This removes the former far-corner-first scan and repeated 64-entry farthest-distance searches.

Adjacent routes reuse already checked safe terrain edges. Longer routes to an out-of-window goal can continue at a useful checked frontier without exhausting the whole window. Reached intermediate waypoints advance in the same tick. Descending/final local corrections use ordinary backward/strafe inputs while holding view direction; fresh body-corridor and footprint support checks cover the requested correction, momentum and combined projected travel. Unknown, hazardous or unsupported corrections hold rather than granting unchecked input.

Java 21 deterministic tests cover angular convergence/reversals and complete acceleration bounds, nearest-first coverage, changed/unsafe correction directions and checked frontier search. One fixed frontier fixture reduces expansion count from **81 to 5** at the same node budget. This measures that synthetic search, not Minecraft FPS, real travel speed or public-server performance. The user requested manual gameplay checks; no new native client or long gameplay sweep is run for this update. Current build/delivery scope is in [VALIDATION.md](VALIDATION.md).
